# Joker Hand 성장과 AI 및 개발 관리

기획 기준 버전 0.2

이 문서는 한 판 바깥의 성장·모드·보상 정책, AI의 판단 기준, 현재 구현 범위와 후속 결정 사항을 정리한다. 정책이 합의됐다는 것과 실제 기능이 존재한다는 것을 구분하여 개발 우선순위와 테스트 기준으로 사용한다.

## 1 성장과 조커 획득

P-01 대전 보상으로 재화를 획득하고 새로운 조커를 획득하는 성장 루프를 사용한다. 기존 Game Design v0.1에서 재화를 사용한 랜덤 획득과 중복 조커 강화가 확정 방향으로 기록됐다. 구체적인 상점·뽑기 UI, 확률, 비용과 천장은 아직 미결정이다.

P-02 신규 플레이어에게 서로 다른 기본 조커 3종을 무료 지급한다. 지급 대상은 유지·활용형, 결단형, 페어형이다. 지급 시점·계정 저장·중복 지급 방지 절차는 구현 전 상세 설계가 필요하다.

P-03 같은 조커를 중복 획득하여 강화하는 방향은 유지한다. 후보 3슬롯에는 같은 종류를 두 번 넣을 수 없다. 조커 강화 단계, 필요 중복 수량, 소모 재화, 최대 레벨, 실패 여부는 미결정이다.

P-04 기존 기획의 높은 희귀도에 따른 성능·전략 다양성 방향은 남아 있다. 희귀도 등급과 실제 성능 차이는 확정하지 않았으며, 공유 52장 일반 덱의 구성 자체를 바꾸는 기능이 확정된 것은 아니다. 희귀도와 강화가 PvP 성능을 얼마나 변화시키는지 검증해야 한다.

P-05 현금 결제, 광고, 배틀패스, 시즌, 스킨은 현재 확정된 사업 모델이 아니다. 초기 기획 정리를 위해 임의로 추가하지 않는다.

## 2 승패와 보상 정책

| 결과 또는 조건 | 보상 정책 | 구현 상태 |
|---|---|---|
| 정상 승리 | 정상 무승부보다 높은 재화 | 미구현 |
| 정상 무승부 | 승리보다 낮고 패배보다 높은 재화 | 미구현 |
| 정상 패배 | 재화 지급, 정상 결과 중 가장 낮음 | 미구현 |
| AI 난이도 | 같은 결과라면 초급보다 중급, 중급보다 고급의 보상이 높음 | 미구현 |
| 자발적 기권 | 기권자 보상 없음 | 기권 승패만 구현 |
| 연결 종료로 이탈 | 기권 처리, 이탈자 보상 없음 | 네트워크 미구현 |
| 상대 기권 후 남은 플레이어 | 즉시 승리, 정상 승리 보상 | 승패만 구현 |

보상 관계는 ‘승리 > 무승부 > 패배’, 같은 결과의 AI 보상은 ‘고급 > 중급 > 초급’이다. 실제 수량, 1일 제한, 반복 플레이 악용 대응, 친구 대전 보상, 보상 지급 시점과 서버 중복 지급 방지는 미결정이다.

## 3 PvP와 매칭

P-06 실시간 PvP에서도 플레이어의 강화 수치를 유지한다. 노력으로 얻은 성장을 제거하지 않는 대신 신규 플레이어 보호와 실력·출전 후보 강도를 고려한 매칭을 사용한다는 방향을 합의했다.

P-07 매칭 강도는 실제 후보 3종을 고려해야 한다. 강한 후보 1종과 약한 후보 2종을 편성해 평균값을 낮추는 방식이 유리하지 않도록 가장 강한 후보의 영향도 검토한다. 정확한 산식, 허용 격차, 신규 보호 기간과 실력 지표는 미결정이다.

P-08 상대가 대전 시작 시 후보의 조건과 강화 수준·실제 수치를 확인할 수 있어야 한다. 상대만 추가 정보를 얻는 정보 비대칭을 만들지 않는다.

친구 대전은 짧고 가벼운 대전 경험의 방향으로 남아 있다. 초대 코드, 친구 목록, 방 생성, 관전, 재대결 방식은 미결정이다. 낮은 접속자 수를 보완할 AI 대체 매칭은 후보 정책이며, 인간으로 위장한 AI를 자동 투입하는 정책을 확정한 것은 아니다. 비동기 PvP와 고스트 상대도 초기 구현 범위 밖의 검토 후보다.

기존 문서에서 언급한 Fusion 2는 기술 검토 맥락으로 보존한다. 현재 네트워크 기술 스택이 선정되거나 적용된 상태로 기록하지 않는다.

## 4 AI 기획

### 4 1 역할과 난이도

AI는 플레이어 수가 부족해도 정상적인 1대1 대전을 제공하고 핵심 루프를 테스트하는 상대다. 초급·중급·고급의 세 난이도 구성을 사용하며 첫 프로토타입은 중급부터 구현한다.

AI-01 인간과 동일한 정보 제한을 지킨다. 자신의 카드와 공개된 공용 카드·버린 카드·후보를 사용할 수 있지만 상대의 개인 카드, 실제 덱 순서, 다음 공용 카드, 상대의 미확정 선택과 예측은 볼 수 없다.

AI-02 난이도 차이는 정보 치팅으로 만들지 않는다. 판단 깊이, 근사 계산, 실수와 성향 등으로 구분한다. 초급과 고급의 구체적인 오류율·성향·탐색량은 미결정이다.

AI-03 강한 AI와 인간다운 AI는 별도로 검증한다. 기존 요구의 판단 차이·안정적 또는 공격적 플레이·상대 대응 성향은 방향이며 현재 모든 성격 모델이 구현됐다는 뜻은 아니다. 머신러닝이나 강화학습을 사용해야 한다는 요구도 없다.

### 4 2 현재 중급 AI

교체 단계에서는 0장, 첫 카드, 두 번째 카드, 두 장 교체를 비교한다. 각 선택에 대해 가능한 새 카드와 네 번째 공용 카드를 표본으로 만들고, 그 뒤 조커를 선택했을 때 기대할 수 있는 평균 점수를 평가한다.

조커 선택 단계에서는 현재 알려진 카드들을 제외한 모든 다섯 번째 공용 카드 후보를 고려한다. 각 조커의 평균 최종 점수를 계산하여 높은 쪽을 선택한다. 현재 점수만 높은 조커가 아니라 마지막 카드로 얻을 수 있는 추가 보상도 고려한다.

예측형은 현재 모르는 카드 중 남아 있을 가능성이 있는 수가 가장 많은 숫자를 우선하고, 그 숫자의 가능한 무늬 하나를 지정한다. 실제 마지막 카드를 본 뒤 예측을 바꾸지 않는다.

| 구현 파라미터 | 현재 값 | 상태 |
|---|---|---|
| 교체 선택 수 | 4개 | 규칙에서 파생 |
| 선택별 교체·네 번째 카드 표본 | 48개 | 구현 선택 |
| 각 표본의 마지막 카드 후보 | 최대 12개 | 구현 선택 |
| 상대의 교체 장수 추정 | 0·1·2장을 균등하게 가정 | 구현 선택 |
| 조커 선택의 마지막 카드 평가 | 알려진 카드를 제외한 후보 전부 | 구현 선택 |
| 목표 | 자신의 평균 최종 점수 최대화 | 중급 프로토타입 정책 |

현재 중급은 상대의 점수 분포를 추정해 승률을 직접 최대화하지 않으며 상대 습관을 학습하지 않는다. 상대의 비공개 개인 카드도 AI 관점에서는 모르는 카드이므로 후보에 포함될 수 있다. 이는 불확실성을 계산하는 방식이며 실제 게임 덱에 카드를 재삽입하는 동작은 아니다.

시간 초과 자동 선택과 중급 AI 선택은 구분한다. 자동 선택은 현재 카드 기준 점수만 비교하고 예측을 생성하지 않는다. AI는 제한시간 안에 의사결정을 내리면서 마지막 카드 가능성과 예측 값을 선택할 수 있다.

## 5 현재 구현 현황

| 영역 | 구현 상태 | 비고 |
|---|---|---|
| 공유 52장 덱과 개인·공용 카드 | 구현 | 카드 중복과 버린 카드 재사용 방지 |
| 교체와 조커 선택 | 구현 | 동시 잠금, 15초·30초, 자동 확정 |
| 족보 및 숫자 보정 | 구현 | 최선의 5장, 동급 선택 최적화 |
| 조커 6종과 예측 | 구현 | 기본·추가 효과, 예측 지연 공개 |
| READY와 현재 점수 | 기능 화면 구현 | 최종 UI와 모바일 사용성 검증 필요 |
| 결과 공개와 승패 | 구현 | 약 5초 단계 공개, 정수 동점 무승부 |
| 중급 AI | 구현 | 공개 정보 기반 평균 점수 정책 |
| 초급·고급 AI | 미구현 | 난이도 세부 기준도 미결정 |
| 조커 획득·강화·재화 | 미구현 | 정책과 테스트 값만 정리 |
| 실시간 PvP·매칭·재접속 | 미구현 | 상세 정책·기술 선택 필요 |
| 랭킹·친구 화면·모바일 완성 UI | 미구현 | 관련 요구와 후보 방향만 존재 |

현재 프로젝트는 Unity 6000.6.0f1이다. 전용 장면은 Assets/Scenes/JokerHandPrototype.unity이며 Unity 메뉴의 Joker Hand → Open Prototype에서 열어 Play로 실행한다. 화면은 기능 검증용 IMGUI다. 초기 선택 세트는 무료 지급 정책을 반영한 기본 구성일 뿐 실제 계정 지급·보유 저장은 아니다.

코드 연결: Cards는 카드·조커 식별, Poker는 족보 판정, Scoring은 효과 계산, Match는 단계·공개 규칙, MediumAi는 의사결정, Prototype은 테스트 화면을 담당한다. 파일은 Assets/JokerHand 아래에 있으며 사용자용 기획 규칙과 구현 세부를 혼합해 새 요구로 간주하지 않는다.

## 6 검증 현황과 다음 테스트

현재 기록된 자동 검사 결과는 핵심 검사 274개 통과다. 여기에는 2,598,960개의 5장 조합 분류, 숫자 강도와 경계, 조커 조건, 시간 초과, 정보 공개, 100판의 카드 중복·재사용 방지와 AI 정보 제한 검사가 포함된다. Unity 컴파일·장면 생성과 Play Mode에서 AI 상대 한 판을 완료하는 검사 1개도 통과했다.

이 결과는 모든 게임 진행의 전수 검증, 시각 품질, 입력 사용성 또는 밸런스 검증 완료를 의미하지 않는다. Unity 실행 검사는 그래픽 출력 없는 자동 실행이었다. 로컬 검증 명령은 Tests/RunCoreChecks.ps1이고 Unity 결과 기록은 Logs/JokerHand-PlayMode.xml이다.

| 후속 검증 질문 | 기록할 지표 | 현재 판정 기준 |
|---|---|---|
| 짧고 반복 가능한가 | 한 판 시간, 단계별 결정 시간 | 60초 미만도 허용, 강제 대기 없음 |
| 15초·30초가 충분한가 | 선택 시간, 자동 확정 비율, 실수 이유 | 수치 목표 미결정 |
| 조커 선택이 달라지는가 | 후보 구성·현재 패별 선택률 | 특정 후보가 항상 정답인지 확인 |
| 큰 역전이 납득 가능한가 | 역전 원인, 예측 적중, 점수 설명 이해도 | 수치 목표 미결정 |
| 점수형과 배율형의 역할이 다른가 | 족보별 보너스 비중·승률 | 조커별 성능 목표 미결정 |
| 신규와 성장 플레이어가 공정한가 | 성장 격차·매칭 대기·승률 | PvP 구현 후 검증 |
| AI가 불공정하게 느껴지는가 | 공개 정보 준수, 반복 행동, 체감 난이도 | 정보 치팅 불가, 난이도 목표 미결정 |

특정 판수나 조커 수를 채웠다는 이유만으로 검증이 충분하다고 결론 내리지 않는다. 여섯 조커는 초기 검증 범위이며 최종 콘텐츠 수가 아니다.

## 8 미결정 사항 관리

아래 우선순위는 개발 의존성을 정리한 관리 기준이며 새 출시 일정이나 사용자 승인 규칙을 뜻하지 않는다.

| ID | 미결정 항목 | 다음 결정이 필요한 시점 |

## 9 문서 운영

Google Docs를 편집용 기획 문서로 사용하고, 프로젝트 Document 폴더에는 같은 기준선의 읽기용 Markdown 사본과 문서 링크를 보관한다. 현재 사본은 자동 동기화되지 않는다. 기획 변경 시 해당 Google Docs와 로컬 사본, 변경 이력 및 관련 테스트를 함께 갱신한다.

기획 확인은 Document/README.md에서 시작한다. 변경 전 Google Docs의 최신 내용과 로컬 사본의 차이를 확인하고, 후속 사용자 결정을 우선한다. 미결정 항목이 해결되면 해당 ID의 상태를 갱신하되 기존 확정 규칙을 조용히 덮어쓰지 않는다.
